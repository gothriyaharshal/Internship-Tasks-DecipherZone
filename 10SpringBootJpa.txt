Step 3: Entity
package com.entity;

import jakarta.persistence.*;

@Entity
@Table(name="student")
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;

    private String name;

    private String course;

    private double fee;

    public Student() {
    }

    public Student(Integer id, String name, String course, double fee) {
        this.id = id;
        this.name = name;
        this.course = course;
        this.fee = fee;
    }

    public Integer getId() {
        return id;
    }

    public void setId(Integer id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getCourse() {
        return course;
    }

    public void setCourse(String course) {
        this.course = course;
    }

    public double getFee() {
        return fee;
    }

    public void setFee(double fee) {
        this.fee = fee;
    }
}

Step 6: Service Implementation
package com.service;

import java.util.List;

import org.springframework.stereotype.Service;

import com.entity.Student;
import com.repository.StudentRepository;

@Service
public class StudentServiceImpl implements StudentService {

    private final StudentRepository repository;

    public StudentServiceImpl(StudentRepository repository) {
        this.repository = repository;
    }

    @Override
    public Student saveStudent(Student student) {

        return repository.save(student);
    }

    @Override
    public Student updateStudent(Integer id, Student student) {

        Student dbStudent = repository.findById(id)
                .orElseThrow(() -> new RuntimeException("Student Not Found"));

        dbStudent.setName(student.getName());
        dbStudent.setCourse(student.getCourse());
        dbStudent.setFee(student.getFee());

        return repository.save(dbStudent);
    }

    @Override
    public Student getStudent(Integer id) {

        return repository.findById(id)
                .orElseThrow(() -> new RuntimeException("Student Not Found"));
    }

    @Override
    public List<Student> getAllStudents() {

        return repository.findAll();
    }

    @Override
    public void deleteStudent(Integer id) {

        repository.deleteById(id);
    }

}
Why don't we use @Transactional here?
In Spring Boot Data JPA:

SimpleJpaRepository (the class that implements JpaRepository) is already transactional:

Read methods → @Transactional(readOnly = true)

Save/Delete methods → @Transactional

So this works:

repository.save(student);
without adding

@Transactional
You usually add @Transactional on the service when:

Multiple repository calls must succeed or fail together.

You modify lazy-loaded entities within one transaction.

You need explicit transaction boundaries for business logic.

Step 7: Controller
package com.controller;

import java.util.List;

import org.springframework.web.bind.annotation.*;

import com.entity.Student;
import com.service.StudentService;

@RestController
@RequestMapping("/students")
public class StudentController {

    private final StudentService service;

    public StudentController(StudentService service) {
        this.service = service;
    }

    @PostMapping
    public Student save(@RequestBody Student student) {

        return service.saveStudent(student);
    }

    @GetMapping("/{id}")
    public Student getStudent(@PathVariable Integer id) {

        return service.getStudent(id);
    }

    @GetMapping
    public List<Student> getAllStudents() {

        return service.getAllStudents();
    }

    @PutMapping("/{id}")
    public Student update(@PathVariable Integer id,
                          @RequestBody Student student) {

        return service.updateStudent(id, student);
    }

    @DeleteMapping("/{id}")
    public String delete(@PathVariable Integer id) {

        service.deleteStudent(id);

        return "Deleted Successfully";
    }

}

How save() works internally
When you call:

repository.save(student);
The flow is:

StudentRepository
       │
       ▼
SimpleJpaRepository.save(entity)
       │
       ▼
EntityManager.persist(entity)   // if new entity (id is null)
or

EntityManager.merge(entity)     // if entity already exists (id is not null)
Then:

Hibernate
      │
      ▼
Generates SQL
      │
      ▼
INSERT INTO student(...)
or

UPDATE student
SET ...
WHERE id = ?
Comparison of all persistence approaches
Feature	Standalone Hibernate	Spring Hibernate	Spring Data JPA	Spring Boot + Spring Data JPA
XML configuration	Yes	Optional	No	No
SessionFactory	Manual	Managed by Spring	Hidden	Hidden
EntityManager	No	Yes	Yes	Yes
Repository interface	No	No	Yes	Yes
CRUD implementation	Manual	Manual	Auto-generated	Auto-generated
SQL writing	Usually No	Usually No	No	No
Transaction management	Manual	@Transactional	Mostly handled by repository	Mostly handled by repository
Embedded server	No	No	No	Yes (Tomcat by default)
Production usage	Rare	Less common	Common	Most common
This is the standard layered architecture used in most modern Spring Boot applications.
