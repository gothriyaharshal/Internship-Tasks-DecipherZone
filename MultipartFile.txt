This is actually one of the most important topics in Spring Boot. Many beginners find it difficult because it combines Spring Boot + HTTP + Multipart files + Java File I/O + Database.

The good news is that you do not need to master Java File I/O first to upload files in Spring Boot. Spring provides MultipartFile, which makes it much easier.

How does Spring Boot receive an image?

Suppose your frontend sends:

Title
Content
Image

The request is not JSON.

Instead it is:

multipart/form-data

because JSON cannot directly contain a binary image file.

Your controller looks like:

@PostMapping("/posts")
public ResponseEntity<?> createPost(

        @RequestParam String title,

        @RequestParam String content,

        @RequestParam MultipartFile image
) {

}

Notice:

MultipartFile image

Spring automatically receives the uploaded file.

What is MultipartFile?

Think of it as a Java object representing the uploaded file.

MultipartFile

------------------

------------------

Useful methods include:

returns

2048000

How do we save it?

Spring provides:

image.transferTo(destination);

Example:

Path path = Paths.get("uploads/images/" + image.getOriginalFilename());

image.transferTo(path);

That's all.

You don't need FileOutputStream.

Spring writes the file for you.

Yes, but after you're comfortable with Spring Boot CRUD.

FetchType

This is one of the most important concepts.

Suppose database contains

User

1 Harshal

Posts

Java

Spring

Hibernate
EAGER Loading
fetch = FetchType.EAGER

means

Whenever User is fetched, fetch Posts immediately.

You execute

User user = userRepo.findById(1).get();

JPA automatically does something like

SELECT * FROM user;

SELECT * FROM post WHERE user_id=1;

Even if you never use

user.getPostList()

Posts are already loaded into memory.

LAZY Loading
fetch = FetchType.LAZY

means

Don't load posts immediately.

You do

User user = userRepo.findById(1).get();

Only this query runs

SELECT * FROM user;

No post query.

Later, when you write

user.getPostList();

Only then Hibernate executes

SELECT * FROM post WHERE user_id=1;

This saves memory and improves performance when related data isn't always needed.

Visual Difference
EAGER
find User
     │
     ▼
User
     │
     ▼
Posts automatically loaded
LAZY
find User
     │
     ▼
User only

Later

user.getPostList()
       │
       ▼
Now Posts are loaded
Which should you use?

In most Spring Boot applications:

@ManyToOne defaults to EAGER.
@OneToMany defaults to LAZY.

For a blog application, keeping @OneToMany as LAZY is usually a good choice because when you fetch a user, you don't always need every post they've written.
