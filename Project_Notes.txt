how did i achieve Exception handling in Spring boot

Exception Handling is one of the most important topics in Spring Boot. Every REST API should handle exceptions gracefully instead of showing a long stack trace.

Why do we need Exception Handling?

Suppose your API is:

GET /users/100

But only users 1, 2, 3 exist.

Without exception handling, Spring Boot returns:

{
    "timestamp": "...",
    "status": 500,
    "error": "Internal Server Error",
    "trace": "Very long stack trace..."
}

This is:

❌ Not user-friendly.
❌ Exposes internal application details.
❌ Not suitable for production.

Instead, we want:

{
    "message": "User not found with id : 100",
    "success": false
}

Step 1: Create a Custom Exception
package com.blog.blog_app.exceptions;

public class ResourceNotFoundException extends RuntimeException {

    public ResourceNotFoundException(String message) {
        super(message);
    }
}
Step 2: Throw the Exception

Instead of:

User user = repository.findById(id).get();

write:

User user = repository.findById(id)
        .orElseThrow(() ->
                new ResourceNotFoundException("User not found with id : " + id));

If the user doesn't exist, Spring throws your custom exception.

Step 3: Create a Global Exception Handler
package com.blog.blog_app.exceptions;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<String> resourceNotFound(ResourceNotFoundException ex) {

        return new ResponseEntity<>(
                ex.getMessage(),
                HttpStatus.NOT_FOUND
        );
    }
}

Now every ResourceNotFoundException is handled here.

Instead of returning only a string, create a response class.

Global Exception Handler

@ExceptionHandler(ResourceNotFoundException.class)
public ResponseEntity<ApiResponse> resourceNotFound(ResourceNotFoundException ex){

    ApiResponse response =
            new ApiResponse(ex.getMessage(), false);

    return new ResponseEntity<>(
            response,
            HttpStatus.NOT_FOUND
    );
}

Response:

{
    "message":"User not found with id : 100",
    "success":false
}

This is the style used in many production APIs.

Handle Multiple Exceptions
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ApiResponse> handleResource(
            ResourceNotFoundException ex){

        ApiResponse response =
                new ApiResponse(ex.getMessage(), false);

        return new ResponseEntity<>(
                response,
                HttpStatus.NOT_FOUND
        );
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiResponse> handleAll(
            Exception ex){

        ApiResponse response =
                new ApiResponse(ex.getMessage(), false);

        return new ResponseEntity<>(
                response,
                HttpStatus.INTERNAL_SERVER_ERROR
        );
    }

}

The second method catches any exception that you haven't handled specifically.

Why @RestControllerAdvice?

@RestControllerAdvice is a global exception handler.

Instead of writing try-catch in every controller:

try{

}
catch(Exception e){

}

Spring automatically sends every matching exception to your handler.

Interview Questions
1. Why create a custom exception?

To provide meaningful, application-specific error messages instead of generic exceptions.

2. Why extend RuntimeException?

Because it is an unchecked exception, so you don't have to declare it with throws in every method.

3. Why use @RestControllerAdvice?

To centralize exception handling for all REST controllers and avoid repeating try-catch blocks.

4. Difference between @ControllerAdvice and @RestControllerAdvice
@ControllerAdvice	@RestControllerAdvice
Used with Spring MVC	Used with REST APIs
Usually returns views (JSP/Thymeleaf)	Returns JSON responses
Equivalent to @ControllerAdvice + @ResponseBody?	Yes
