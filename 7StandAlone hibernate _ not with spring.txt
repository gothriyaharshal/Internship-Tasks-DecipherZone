Step 3 Entity Class
package entity;

import jakarta.persistence.*;

@Entity
@Table(name="users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private int id;

    @Column(name="name")
    private String name;

    @Column(name="email")
    private String email;

    @Column(name="city")
    private String city;

    public User() {
    }

    public User(String name, String email, String city) {
        this.name = name;
        this.email = email;
        this.city = city;
    }

    public int getId() {
        return id;
    }

    public void setId(int id) {
        this.id=id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name){
        this.name=name;
    }

    public String getEmail(){
        return email;
    }

    public void setEmail(String email){
        this.email=email;
    }

    public String getCity(){
        return city;
    }

    public void setCity(String city){
        this.city=city;
    }

}

Step 5 Hibernate Utility
package util;

import org.hibernate.SessionFactory;
import org.hibernate.cfg.Configuration;

public class HibernateUtil {

    private static SessionFactory sessionFactory;

    static {

        sessionFactory = new Configuration()
                .configure("hibernate.cfg.xml")
                .buildSessionFactory();

    }

    public static SessionFactory getSessionFactory(){

        return sessionFactory;
    }

}

public void saveUser(User user){

    Session session =
            HibernateUtil.getSessionFactory().openSession();

    Transaction tx = session.beginTransaction();

    session.persist(user);

    tx.commit();

    session.close();

}

public List<User> getAllUsers(){

UPDATE
public void updateUser(int id){

    Session session =
            HibernateUtil.getSessionFactory().openSession();

    Transaction tx =
            session.beginTransaction();

    User user =
            session.get(User.class,id);

    user.setCity("Delhi");

    tx.commit();

    session.close();

}
Notice that there is no explicit session.update(user) here. Since the entity was loaded in the same session, it is in the persistent state. Hibernate's dirty checking detects that city changed and automatically issues an UPDATE when the transaction commits.

Why Transaction Is Needed
For operations that modify data (INSERT, UPDATE, DELETE), Hibernate requires a transaction.

Transaction tx = session.beginTransaction();

...

tx.commit();
Without committing:

persist()

↓

SQL prepared

↓

No Commit

↓

Nothing saved
For simple reads (SELECT), you can often omit a transaction in standalone Hibernate, although many applications still use one for consistency.

Entity States (Very Important)

⬇ session.close()

⬇ remove()

Removed

(Marked for deletion and deleted on commit)

Methods You Should Know
Method	Purpose
persist()	Save a new entity

commit()	Save changes
rollback()	Undo changes if an error occurs
close()	Release session resources
What comes next?
Once you're comfortable with this standalone Hibernate CRUD, the progression is:

Hibernate (Standalone) – You manually create the SessionFactory, Session, and transactions.

Spring ORM + Hibernate – Spring manages the SessionFactory and transactions (@Transactional) for you.

Spring Data JPA (without Spring Boot) – You use repositories like JpaRepository instead of writing most DAO code yourself.

Spring Boot + Spring Data JPA – Spring Boot auto-configures Hibernate, the datasource, and repositories, so you write the least amount of configuration.

Understanding the standalone version first makes it much easier to appreciate what Spring is automating behind the scenes.
